> **"You can't ship code you don't understand. Let's make sure you understand."**
>
> A Socratic teaching agent that intercepts AI code generation requests and asks 3 targeted questions before delivering code. Prevents **cognitive debt** — the new failure mode where AI-generated code ships to production without any human truly knowing how it works.

---

## The Problem: Cognitive Debt in Vibe Coding

Before AI code generation, developers faced **technical debt** — code that worked but was hard to maintain. AI coding tools like Claude and Copilot have introduced a new, more dangerous category: **cognitive debt** — code that works but that no human on the team actually understands.

```
Production incident. Nobody knows why it happened.
→ The code was generated by an LLM 6 months ago.
→ The developer who "wrote" it vaguely remembers approving it.
→ Nobody can debug it because nobody understands it.
```

The psychology is subtle but devastating. A developer who copies from Stack Overflow at least *knows* they copied. A developer who watches Claude generate 200 lines, sees it work, and ships it — genuinely *believes* they understand it. They built it with AI, after all.

This agent exists to break that illusion — not harshly, but through the oldest teaching method in human history: **asking questions**.

---

## What It Does

```bash
# Instead of:
$ claude "write a payment handler"

# You run:
$ socratic claude "write a payment handler"
```

The agent intercepts the request and asks **exactly 3 Socratic questions** before generating any code:

```
🤔 SOCRATIC MODE — 3 questions before code

🔴 Q1 (QUAN TRỌNG): If the user clicks "Pay" twice in rapid succession —
    or the client retries on timeout — what happens to their balance?

🟡 Q2: If the balance decrement succeeds but the transaction log write fails,
    where is the money? What state is your data in?

🟢 Q3: What does the caller of this function receive when payment fails?
    Exception, error code, or null? Is it consistent with the rest of the API?

👉 Your answer:
```

**Your answer determines what happens next:**

| Your Answer | Agent Response |
|---|---|
| Deep understanding | Full code with celebration + annotations |
| Partial understanding | Core logic delivered, gaps flagged for you to fill |
| "I don't know" | Brief teaching of the concept, then safe minimal version |
| "Just give me the code" | Code delivered with risk warnings — no lecture |
| Production emergency | Questions skipped entirely, code with "review these 3 things" note |

## Quick Start

### CLI

```bash
npx socratic claude "viết hàm chuyển tiền giữa 2 tài khoản"
npx socratic --lang python copilot "write a rate limiter"
npx socratic --dev dev-001 --batch claude "simple config file"
```

### API

```typescript
import {
  Orchestrator,
  type CodeRequest,
  type PipelineResult,
} from '@vibe-socratic/reviewer-agent';

const orchestrator = new Orchestrator();

const request: CodeRequest = {
  id: 'req-001',
  rawPrompt: 'Write a payment handler that deducts from user balance',
  language: 'typescript',
  context: { urgency: 'normal' },
};

// Step 1: Intercept the request — get back 3 questions
const result = await orchestrator.intercept(request, 'dev-001');
for (const q of result.questions) {
  console.log(`[${q.tier}] ${q.text}`);
}

// Step 2: Submit developer answers
const fullResult = await orchestrator.fullFlow(request, 'dev-001', [
  'Use idempotency keys — client generates UUID per intent, server checks before processing...',
  'Wrap both operations in a database transaction — both succeed or both roll back...',
  'Throw typed errors so the caller can distinguish network failures from validation failures...',
]);

console.log(fullResult.unlock?.type);         // "FULL_UNLOCK"
console.log(fullResult.unlock?.celebration);  // "You've identified idempotency, database-transactions..."
console.log(fullResult.annotatedCode);        // AnnotatedCode with WHY/RISK/CONSIDER/DANGER annotations
```

## The 7 Operating Modes

| Mode | Trigger | Behavior |
|---|---|---|
| `SOCRATIC` | Complex request with blind spots | 3 questions → evaluate → unlock |
| `ANNOTATED` | Simple request / low risk | Generate code with WHY/RISK/CONSIDER/DANGER annotations |
| `EMERGENCY` | Production urgency detected | Skip all questions, generate with "revisit later" notes |
| `TRUSTED` | All concepts already mastered | Skip questions — generate annotated code |
| `REVERSE_SOCRATIC` | Developer pastes code for explanation | "You explain first, I'll correct" |
| `AUDIT` | Code review request | Identify 3 critical concerns, ask about them |
| `TRANSPARENT_CHOICE` | Developer says "just give me the code" | Warn about risks, deliver code |

## The 10 Blind Spot Categories

Every AI-generated code request is analyzed for these risk patterns:

| # | Blind Spot | Severity | Example Trigger |
|---|---|---|---|
| 1 | SQL Injection | CRITICAL | User input flowing into query without parameterization |
| 2 | Missing Transaction | CRITICAL | Multiple writes without atomicity guarantee |
| 3 | Authorization Bypass (IDOR) | CRITICAL | Document access by ID without ownership check |
| 4 | Double Spend / Idempotency | CRITICAL | Payment operations without idempotency key |
| 5 | Lost Update (Race Condition) | HIGH | Read-modify-write without concurrency control |
| 6 | Connection Leak | HIGH | Resource open without cleanup on error paths |
| 7 | Silent Error | HIGH | Catch block swallows exception, caller unaware |
| 8 | N+1 Query | MEDIUM | Database query inside loop |
| 9 | Wrong Data Structure | MEDIUM | Array search where Map/Set would be O(1) |
| 10 | Cache Invalidation | MEDIUM | Cache without staleness detection |

Each category has **multiple Vietnamese and English keyword triggers** for reliable detection across languages.

## Understanding Graph — Never Ask the Same Question Twice

The agent tracks every developer's understanding across sessions via SQLite:

```typescript
interface DeveloperUnderstandingGraph {
  developerId: string;
  masteredConcepts: ConceptMastery[];     // Won't ask about these again
  learningConcepts: ConceptInProgress[];  // Will probe gently
  gapConcepts: ConceptGap[];              // Known weak spots
  trajectory: {
    conceptsLearnedCount: number;
    incidentsPreventedEstimate: number;
    totalSocraticSessions: number;
  };
}
```

A concept demonstrated once (via a DEEP answer) is **never asked about again**. A concept mentioned proactively (without being prompted) is recorded as mastered immediately — that's the highest form of understanding.

The concept dependency graph prevents asking advanced questions before basics: you won't be asked about `transaction-isolation` until you've shown mastery of `database-transactions`.

## Code Annotation System

Even when Socratic mode is not triggered, all generated code receives context annotations:

```typescript
// WHY: Bcrypt at 12 rounds gives ~250ms/hash — fast enough for login UX,
//      slow enough to make brute force economically infeasible at scale.
const BCRYPT_ROUNDS = 12;

// RISK: jwt.verify throws if the token is expired, malformed, or signed with
//       the wrong secret. Wrap in try-catch or let the error boundary handle it.
const userId = jwt.verify(token, process.env.JWT_SECRET).sub;

// CONSIDER: This eager-loads ALL posts for ALL users. For datasets above
//           1000 users, switch to paginated queries or lazy loading.
const users = await User.findAll({ include: [{ model: Post }] });

// DANGER: A hanging transaction locks rows on your database. If an exception
//         is thrown before COMMIT, you MUST call ROLLBACK in the catch block.
//         Without this, your connection pool will exhaust under load.
await conn.execute('BEGIN');
```

Annotation types: **WHY** (design rationale), **RISK** (assumptions and failure modes), **CONSIDER** (trade-offs accepted), **DANGER** (critical errors if mishandled).

## Question Quality System

The agent continuously improves its questions by tracking effectiveness:

- **Effectiveness scoring**: Each question is scored based on developer answer depth, issue detection, and explicit feedback
- **Automatic retirement**: Questions answered DEEP >80% of the time are retired as "too easy." Questions answered MISSING >70% of the time are retired as "too hard." Questions with >50% thumbs-down rate are retired.
- **Concept-level analytics**: Track which concepts produce the most real issue discoveries

```typescript
const summary = orchestrator.getQualitySummary();
// {
//   totalQuestions: 247,
//   activeQuestions: 211,
//   retiredQuestions: 36,
//   averageEffectiveness: 1.82,
//   bestConcept: "idempotency",
//   worstConcept: "cache-invalidation"
// }
```

## API Reference

### Orchestrator

The main entry point. Manages the full pipeline.

```typescript
class Orchestrator {
  // Step 1: Analyze request → classify mode → detect blind spots → generate questions
  intercept(request: CodeRequest, developerId: string): Promise<PipelineResult>;

  // Step 2: Evaluate developer answers → determine unlock level
  evaluateAnswers(questions: SocraticQuestion[], answers: string[], developerId: string): Promise<{
    evaluations: AnswerEvaluation[];
    unlock: UnlockDecision;
    teachingMessage?: string;
  }>;

  // Step 3: Annotate code based on unlock level
  deliverCode(code: string, language: string, unlock: UnlockDecision): Promise<AnnotatedCode>;

  // Full flow: intercept → generate → evaluate → unlock → annotate
  fullFlow(request: CodeRequest, developerId: string, answers: string[]): Promise<PipelineResult>;

  // Review existing code for blind spots
  reviewExistingCode(code: string, language: string, developerId: string): Promise<{
    blindSpots: BlindSpot[];
    annotations: AnnotatedCode;
  }>;

  // Reverse Socratic — ask questions about pasted code
  explainThisCode(code: string, developerId: string): Promise<{
    questions: SocraticQuestion[];
    annotation: string;
  }>;

  getQualitySummary(): QuestionQualitySummary;
  getDeveloperGraph(developerId: string): DeveloperUnderstandingGraph;
}
```

### Key Types

```typescript
interface CodeRequest {
  id: string;
  rawPrompt: string;
  language: 'typescript' | 'javascript' | 'python' | 'go' | 'java' | 'unknown';
  context?: {
    urgency?: 'normal' | 'production';
    developerMessage?: string;
    currentFile?: string;
    projectContext?: string;
  };
}

interface SocraticQuestion {
  id: string;
  tier: 'tier1' | 'tier2' | 'tier3';  // Edge case / Design / Critical
  text: string;                         // Vietnamese by default
  blindSpotType: string;                // e.g. "double-spend"
  conceptTested: string;                // e.g. "idempotency"
  specificityScore: number;             // 0–5, penalizes generic questions
}

interface PipelineResult {
  decision: SocraticDecision;
  questions?: SocraticQuestion[];
  evaluations?: AnswerEvaluation[];
  unlock?: UnlockDecision;
  annotatedCode?: AnnotatedCode;
  sessionNote?: string;
}
```

## Why Socratic Method?

The Socratic method — asking questions until understanding is demonstrated — is 2,400 years old and remains the most effective way to distinguish genuine understanding from surface familiarity.

Applied to software engineering:

- **Passive code review**: "Looks good" / "Approved" — tests nothing  
- **Question-based review**: "What happens to your connection if this call fails?" — tests understanding  
- **Socratic conversation**: Series of deepening questions that build from surface to root — **builds** understanding  

Research shows that 67% of AI-generated error handling is inadequate. 82% of payment-related AI code has no idempotency consideration. The questions this agent asks are directly calibrated to close these specific, measurable gaps.

The method works because **answering a question requires retrieval**, which is the most effective form of learning. Reading code is passive. Being asked about it is active. The struggle *is* the learning.
